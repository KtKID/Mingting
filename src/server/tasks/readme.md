# 任务处理

> 草稿，待用户检查。

## 功能描述

发布者可以在同一张任务单里分多轮委托执行。明庭保留原任务编号，按轮保存指令、结果和发单来源。任务服务也处理领取、进度回报、审批、取消、重试、连接中断，以及任务中台的登记与手动派发：发布不填执行者时任务登记为待派发（`awaiting_dispatch`），不触发任何执行者；之后可经网页或 MCP `dispatch` 命令派发给指定执行者。

## 设计理念

一张单用同一个 `taskId` 串起各轮。明庭在数据库事务内为新单创建第 1 轮，每成功追加一次分配下一轮。显式重试沿用原轮次，领取后产生新的运行编号 `runId`。每次执行结束都按既有规则回传本轮结果，由发布者决定继续追加还是结束沟通。 [轮次规则](../../../docs/spec/task-turns-and-seq/tech-design.md#turns)

| 字段                                 | 含义                                                                                                                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `taskTurn`                           | 同一张任务单的执行轮次。首次发布为 `1`，每次成功追加加 `1`。                                                                                                                               |
| `publisherSessionId` 和 `originTurn` | 孔明记录哪一个会话、哪一轮发出了本次指令，并与 `hostId` 一起保存。原发布会话用于校验追加权限，发起轮次用于追溯指令来自该会话的哪一轮。结果默认唤醒该会话，宿主配置了目标会话时按配置投递。 |
| `seq`                                | 同一张单在明庭的收发流水号。首次受理发布为 `1`，此后每条实际收发各加 `1`，跨轮累计。末号就是累计通信条数。                                                                                 |

发布与追加请求、发单回执、派发、领取、执行回报、任务心跳、结果通知、唤醒和确认都按实际消息计数。一次请求及其回应各记一条，结果随唤醒同帧送出时合计一条，独立送出时各记一条。重传按实际收发计数，同一个已受理的发单请求仍沿用原回执和原轮次。连接保活和只读查看详情在计数范围外。连接器回报中的 `seq` 另有自己的作用域，用于校验单次运行的回报顺序。 [通信计数规则](../../../docs/spec/task-turns-and-seq/tech-design.md#sequence)

所有入口共用发布规则。领取时写入限时的执行资格，回报时核对资格和顺序号，避免不同连接器或迟到的回报改写同一次运行。任务、运行和审批一起提交到数据库，客户端再看到更新。 [订阅与领取](../../../docs/HARNESS-SUBSCRIPTIONS.md#h2-定向发布) · [审批裁决](../../../docs/APPROVALS.md#a3-用户优先与十秒窗口)

## 使用方式

### 在孔明发布和追加

孔明的 `mingting-tools` 通过明庭 MCP 的 `mcp-mingting-tool` 发单。两处工具说明都提示「同一任务的后续沟通使用 append，独立的新任务使用 new」。旧调用省略 `action` 时按 `new` 处理。 [工具说明和参数](../../shared/host-wakeup.ts#L4)

1. 首次发布选 `new`。杭州例子第一轮采集出行信息，回执包含任务编号、任务链接、`taskTurn: 1` 和结果订阅凭据。

   ```json
   {
     "action": "new",
     "title": "杭州周末出行规划",
     "description": "采集周末天气、交通和景点信息",
     "publisherName": "Kongming",
     "targetHarness": "Codex"
   }
   ```

2. 上一轮结束、执行释放后，在原发布会话选 `append`，把 `<taskId>` 换成首发回执里的任务编号。明庭沿用原单和执行配置，回执包含同一个任务编号、任务链接和 `taskTurn: 2`。会话来源由孔明自动提供，结果继续用原订阅。

   ```json
   {
     "action": "append",
     "taskId": "<taskId>",
     "description": "根据第一轮的信息生成行程方案"
   }
   ```

3. 收到第二轮结果后，用同一编号追加「核对冲突并生成最终计划」，得到 `taskTurn: 3`。在杭州推演中，这三次指令来自孔明会话的第 4、5、6 轮，明庭任务轮次为 1、2、3。同一张单的通信序号继续累计。 [杭州三轮逐条推演](../../../docs/spec/task-turns-and-seq/tech-design.md#example)

省略 `targetHarness` 的 `new` 只登记为待派发，回执不变但任务不会被执行者感知。之后在网页任务详情点「派发」，或发 `dispatch` 命令交给指定执行者（可覆盖任务原有目标）：

```json
{
  "action": "dispatch",
  "taskId": "<taskId>",
  "targetHarness": "Codex"
}
```

追加适用于有首轮记录、可核验原发布会话的任务。上一轮仍在排队、执行、等待审批或清理时，等执行释放后再追加；待派发的任务需要先派发或取消后重新发布。已有历史单可以照常查看。

明庭任务清单单独显示「状态」和「轮次」。执行中、已取消显示「第 N 轮」，已完成、执行失败显示「共 N 轮」，无轮次记录的历史单显示「—」。打开详情可按轮查看指令、结果和来源，在「投递结果」查看唤醒状态，按 `seq` 翻看「通信记录」。 [轮次显示](../../web/main.tsx#L106) · [投递结果](../../web/main.tsx#L924) · [轮次与通信记录](../../web/main.tsx#L945)

### 应用接口与验证

接口层从 [createPlatform(config)](../transport/http.ts#L26) 取得 `service`。`service.publish(input)` 按[任务发布定义](../../shared/protocol.ts)新建任务并返回回执，MCP 使用 `publishCommand()` 选择新建、追加或派发。连接器通过 [HTTP 接口](../transport/readme.md)领取并回报，网页通过同一服务派发、取消、重试和裁决审批。 [平台集成测试](../../../tests/platform.test.ts)

杭州网页验收从孔明「新建会话」发起，使用固定模型响应触发一次 `new` 和两次 `append`，由真实 Codex 执行。验收记录为一张任务单、三轮各成功唤醒原会话一次、其他测试会话收到零次，通信流水为 `1–1020`。模型自主选择发单动作的表现属于独立验证范围。另有集成用例覆盖第四轮追加、通信计数和投递确认。 [多轮 MCP 集成测试](../../../tests/task-turns.test.ts#L53)

## 代码说明

[TaskService](service.ts) 是网页、MCP 和连接器共用的入口，负责组装模块、广播事件和服务启停。[sweep()](service.ts#L253) 依次检查租约、执行时限、审批时限和用户优先窗口。运行结束时，任务状态、运行状态和待审记录在同一事务内更新。

| 模块 | 负责的规则 |
| --- | --- |
| [publication.ts](publication.ts) | 处理 MCP 新建与追加，保存轮次、订阅凭据、发布来源和领取事件，成功提交后通知连接器。 |
| [harness-registry.ts](harness-registry.ts) | 记录在线执行器、连接代次和能力快照。领取时校验身份是否符合任务指定的执行器。 |
| [runs.ts](runs.ts) | 领取、续期、回报、取消、同轮重试和运行收尾。领取事件绑定任务轮次，回报按单次运行的序号处理。 |
| [approvals.ts](approvals.ts) | 受理审批请求、读取和提交裁决、处理超时与过期。订阅者先给出意见时，网页用户在优先窗口内可直接裁决。 |
| [publisher-subscriptions.ts](publisher-subscriptions.ts) | 分别校验结果和审批订阅凭据，提供结果重放、待审快照和限时等待。 |
| [wakeup/receipts.ts](../wakeup/receipts.ts) | 查询 Codex 聊天唤醒状态，分别校验 DSH 宿主和 Codex 聊天回执。 |
| [progress.ts](progress.ts) | 将运行通知整理为正文、公开思考和工具进度，按工具调用 ID 合并增量，裁剪展示内容并遮盖常见凭据字段。 |

传输层把实际收发交给存储层，由存储层分配任务内的下一个 `seq`。[taskMessage()](../transport/task-communication.ts#L7) · [taskExchange()](../transport/task-communication.ts#L21) · [Store.communication()](../storage/store.ts#L232)
