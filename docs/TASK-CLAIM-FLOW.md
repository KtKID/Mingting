# 明庭任务领取流程

明庭像一张工单台。发起方交单，明庭保存工单和通知，连接器收到通知后申请领单。**领单成功的回执里才有任务正文**，连接器拿到正文后再启动 Codex、ZCode 等执行器。

连接器是明庭的领单组件，运行起来是一个主动连接明庭的 HTTP 客户端进程。当前同机部署默认由明庭拉起，设置 `TASK_CONNECTOR=manual` 时由操作者单独启动。 [服务启动连接器](../src/server/main.ts#L28) · [连接器启动入口](../src/connector/main.ts#L4)

## 1. 发单时先保存工单，指定执行者才写通知

发起方通过普通 MCP 入口调用 `mcp-mingting-tool`。明庭在同一个 SQLite 事务里保存工单（`tasks`）；填写执行者（`targetHarness`）时同时写入带编号的「有单可领」通知（`deliveries`）。即使执行连接器离线，通用发单仍可返回回执，回执包含任务编号和结果订阅凭据，发起方可以用它订阅结果。 [MCP 入口](../src/server/transport/mcp.ts#L30) · [发单事务与回执](../src/server/tasks/publication.ts#L209)

明庭作为任务中台运行：发单**不填执行者时工单只登记为待派发**（`awaiting_dispatch`），不产生通知、不触发任何执行者。之后在网页任务详情点「派发」，或用 MCP `dispatch` 命令携带执行者派发，派发那一刻才写通知。待派发工单可以取消，也不占执行队列上限。 [登记状态](../src/server/storage/store.ts#L376) · [派发事务](../src/server/tasks/publication.ts#L165) · [网页派发路由](../src/server/transport/browser-api/router.ts#L124)

## 2. 连接器上线后自动收通知

连接器启动后主动打开 `GET /connector/events`，登记自己的 Harness 身份，并告诉明庭上次收到了哪个通知编号。这条 HTTP 连接保持打开，明庭可以持续往里面写通知，这就是这里的 SSE 长连接。 [连接器开始订阅](../src/connector/connector.ts#L57) · [明庭登记连接器](../src/server/transport/connector.ts#L31)

| 场景                       | 连接器怎么发现这张单                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| 发单时已经在线             | 明庭提交工单后，向匹配目标 Harness 的在线连接器实时推送通知。                                 |
| 发单时离线，后来上线或重连 | 明庭根据连接器上报的最后一个通知编号，从 `deliveries` 补发之后的通知。全新连接器从 `0` 开始。 |

两条路径发的是同一种 `task.available` 通知，包含**通知编号、任务编号和通知时间**。明庭按任务目标匹配连接器，连接器把收到的通知放进自己的待领列表。 [通知字段与补读](../src/server/storage/store.ts#L785) · [匹配与推送](../src/server/transport/connector.ts#L69) · [加入待领列表](../src/connector/connector.ts#L75)

## 3. 收到通知后，再发请求正式领单

连接器自动拿着任务编号、通知编号和自己的领取身份，另外发一个 `POST /connector/claim` 请求。明庭在 SQLite **写事务**里按任务编号找这张单，核对通知轮次、连接器身份、任务是否还在排队，以及当前是否有空位。校验通过后，明庭更新 `tasks`，写入 `runs` 和 `leases`，提交后把**任务正文、运行编号和领取凭证信息**返回给连接器。 [发起领单](../src/connector/connector.ts#L154) · [HTTP 入口](../src/server/transport/connector.ts#L133) · [领单事务](../src/server/tasks/runs.ts#L55)

### A、B 同时领单时

- **两人领同一张单。** 假设 A 先提交成功，B 进入领单事务时就会看到任务已被领取，收到 `410`。B 从自己的待领列表移除这条通知。同一连接器的成功回执丢失时，只要原领取仍有效，就可以用原来的领取编号重试，取回同一次运行的回执。
- **两人领不同的单。** A 提交或回滚后就释放 SQLite 写锁，B 随后可以进入自己的领单事务。当前所有 Harness 共用一个执行位，因此 A 的运行还占着位置时，B 会收到 `409`，在本地等 500 毫秒再申请这张已知的单。 [事务提交和回滚](../src/server/storage/store.ts#L302) · [领单冲突判断](../src/server/tasks/runs.ts#L80) · [连接器重试](../src/connector/connector.ts#L180)

**补发通知时按编号读表，确定领取归属时用领单写事务。** 可以把写锁想成工单台只有一支登记笔。A 签完字就把笔交回去，SQLite 的写锁也在这一刻释放。执行任务期间是否还占用名额，由明庭的执行配额决定。

## 4. 领单成功后启动执行器

连接器拿到成功回执后，把任务标题和正文交给适配器，由适配器启动执行器。明庭在成功登记领单时就创建运行和领取凭证，因此执行器启动前，网页上的任务已经可以显示为运行中。 [登记领单](../src/server/tasks/runs.ts#L118) · [开始执行](../src/connector/connector.ts#L191) · [启动执行器](../src/server/harness/acp/acp-adapter.ts#L300)

| 发生了什么                           | 任务状态                                                                                                                     | 其他连接器什么时候能领                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 发布未指定执行者，登记后尚未派发     | **待派发**（`awaiting_dispatch`）。没有通知，认领请求被拒绝。                                                                | 无人可领。网页或 MCP `dispatch` 派发给指定执行者后才进入队列。             |
| 「有单可领」通知已经发出，暂时没人领 | **排队中**（`queued`）。领取凭证在成功领单时才创建。                                                                         | 符合任务目标的连接器可以直接申请。执行位有空时即可领到。                   |
| 明庭已经登记领单，连接器后来失联     | **中断**（`interrupted`）。如果运行仍未结束，领取凭证到期后，明庭结束这次运行并记录失联原因。                                | 等原运行结束后显式重试。任务重新排队后，其他符合条件的连接器可以申请。     |
| 领单后，Agent 启动失败               | **失败**（`failed`）。连接器会尝试上报失败和原因，明庭收到有效回报后保存。如果失败回报也没送到，就走领取凭证到期的中断流程。 | 明庭记下失败后，可显式重试。任务重新排队后，其他符合条件的连接器可以申请。 |

领取凭证当前有效期为 8 秒，从领单成功或最近一次续期开始算。若明庭已经登记领单，连接器只是丢了成功回执，原领取有效期间可以用同一个领取编号取回原回执。 [租约时长](../src/shared/protocol.ts#L41) · [回执重试](../src/server/tasks/runs.ts#L81) · [失败回报](../src/connector/connector.ts#L373) · [写入结束结果](../src/server/tasks/runs.ts#L252) · [凭证到期处理](../src/server/tasks/service.ts#L252)

## 5. 中断或失败后重新排队

中断或失败的工单会停在当前状态，等待显式重试。原运行结束后，在网页点「创建新执行并重试」。只要队列和重试次数还有额度，明庭就保留原任务编号及旧运行记录，把这一轮改回 `queued`，并写入一条编号全新的领取通知。 [网页重试按钮](../src/web/main.tsx#L1328) · [重新排队与发通知](../src/server/tasks/runs.ts#L313)

从重新排队开始，原连接器和其他符合目标 Harness 的连接器都可以来领。**新的运行编号在下一次领单成功时生成。** [校验目标 Harness](../src/server/tasks/harness-registry.ts#L76) · [生成新运行编号](../src/server/tasks/runs.ts#L98)

沿着数据库看这条流程，可以先读 `tasks`、`deliveries`、`runs`、`leases` 这四张表。 [SQLite 建表代码](../src/server/storage/store.ts#L138)
