## ① 需求与变更

用户明确要求补齐当前聊天的两阶段主动唤醒：发布后结束回合，审批事件恢复执行，审批后结束回合，完成事件再次恢复执行并检查成果；保留可回放真实验收。原有主动等待和轮询用例继续承担其原有传输/裁决职责。

基线：Git `5ca8a11`；原有四个 MCP 工具、审批持久化与执行连接器均沿用。新增 W1–W3 的绑定与事件交付，端到端通过须有实际宿主聊天证据。

## ② 精简技术设计

- D1：发布参数增加可选聊天目标，任务与目标在同一事务保存；任务展示数据与私有目标分开保存。新增协议使用共享 Zod 定义。
- D2：审批创建和运行结束与事件写入同一事务。事件 ID 按审批或运行生成，SQLite 唯一键去重。平台提交后的变化通知驱动投递，启动时恢复待投事件。
- D3：复用 CodexAdapter 的 ACP 连接、生命周期与权限桥接，新增 session/load 探测和按原编号 prompt。事件首个模型输出后确认投递，后续事件等待前一回合进程收尾；占用和错误保留实际原因，失败阻止带唤醒发布。
- D4：保存投递结果与实际恢复回合确认。回放校验要求同一聊天、原回合已结束、两次事件与两个新回合对应。投递错误、缺宿主证据及替身分别记录。
- R1/R2：shared → store/adapter → service → HTTP/main，边界由 Zod 解析；R3 为单语言；R4 SQLite 为事件和绑定来源，宿主记录为回合来源；R5 沿用 task/run/approval/thread；R6 超时具名；R7 保留提交点、失败、去重及结果未知状态。

## ④ 技术实现

按 D1–D4 实施：

- `src/shared/task-wakeup.ts`、`protocol.ts`：可选发布绑定、持久事件、宿主状态及恢复确认契约，类型从 Zod 推导；任务公开数据排除私有聊天绑定。
- `src/server/store.ts`：SQLite 绑定与事件表、事件唯一键、事务内写入、待投状态索引；`service.ts`：能力/授权前置、提交后驱动、恢复确认及关闭处理。
- `src/server/task-wakeup.ts`：提交后的事件投递和启动恢复；sending 进程中断保留结果未知，failed 保留错误及尝试次数。

- `src/server/http.ts`：增加 get_wakeup_status、get_task_wakeups、acknowledge_task_wakeup，保持任务订阅凭据校验。
- `src/shared/wakeup-replay.ts`、`scripts/chat-wakeup-live.ts`：真实记录校验与逐回合 HTML，probe/publish/events/ack/replay 命令；发布命令结束后由平台事件承担后续恢复。
- `tests/task-wakeups.test.ts`、`fake-wakeup-host.ts`：9条专项；`tests/platform.test.ts`：更新工具目录预期。package、env示例、README与本功能说明同步。
