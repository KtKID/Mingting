# Codex 任务设置、过程审计与用量对账

用户在明庭发布 Codex 任务时选择模型和思考档位，运行前能看到实际采用的设置，运行中能查看输出、工具和审批，运行后能核对任务消耗、上下文和该次执行的记录。

## 本次目标与完成条件

- **本次目标与范围**：补齐明庭管理的 Codex 任务。在明庭统一设置模型和思考档位，查看生效回执、流式正文与公开思考、工具与审批、任务 Usage 和上下文占用。设置和查询沿用明庭现有任务入口。本次范围限定 Codex 执行任务。其他执行器、桌面聊天唤醒和 Plan Mode 表单属于独立交付范围。
- **验证证据**：用真实 Codex 和已授权账号，从明庭发布一条带显式模型及思考档位的任务。任务在独立测试目录内执行至少一次真实工具操作和一次真实审批。保留所选设置及生效回执、结束前多段正文的观察记录、同次运行的工具和审批结果、Codex 回报的用量和上下文依据，以及明庭对应的记录。用自动检查补验失败、缺项、重试和旧记录边界。
- **完成条件**：下列 10 个场景符合预期。真实任务可从同一次运行记录追溯设置、流式过程、工具审批和最终用量，并逐项核对用量与 Codex 的回报。真实验收任务应拿到生效回执、可对账的任务用量及用于核验的上下文观测。缺少关键证据时，该项继续待验收。
- **范围依据**：本轮用户要求补齐的功能及真实验收目标、现有任务和审批行为。核查证据见 [Codex 接入核查](../../../reports/acp/2026-11-05-Codex-ACP-接入核查.md)、[审批约定](../../APPROVALS.md)和[实时执行约定](../../HARNESS-SUBSCRIPTIONS.md)。

## feat01: 设置 Codex 任务的模型和思考档位

发布 Codex 任务时可指定设置，任务记录能说明实际使用了什么。

场景1: 发布带明确设置的任务
必要性：用户要求设置模型和思考档位并查看生效回执；缺少时无法判断真实任务是否按选择执行。
- GIVEN Codex 对当前账号提供可用模型和对应档位
- WHEN 用户在现有任务入口选择模型和该模型支持的档位并发布任务
- THEN 选择模型时可查看对应的档位，运行记录在执行前显示请求值及 Codex 确认的生效值，并以该设置开始执行

场景2: 沿用项目默认设置
必要性：现有 Codex 任务可以直接发布；缺少时新增设置会阻断原有使用方式。
- GIVEN 用户有权发布 Codex 任务，且项目具备可用默认设置
- WHEN 用户按原流程发布任务并留空模型和思考档位
- THEN 任务按项目默认设置运行，运行记录标明使用默认值，并展示可确认的实际设置

场景3: 显式设置无法生效
必要性：已验证 Codex 会拒绝不支持的档位，任务在意的设置也可能随可用选项变化；缺少时会把使用其他设置的执行误算成验收通过。
- GIVEN 用户提交了明确的模型或档位，但 Codex 无法按选择确认生效
- WHEN 用户查看此次任务的设置回执
- THEN 能看到原请求值和未生效原因，任务在该设置失败处结束，正文、工具和用量不会被归为一次按所选设置执行的成功记录

## feat02: 查看运行过程和工具审批审计

在明庭查看任务的实时输出，结束后可按执行次数查看工具及相应审批。

场景1: 实时观察任务并同意实际工具操作
必要性：用户要求用真实任务验证流式执行和工具审批审计；缺少时无法证明输出、工具、决定与结果来自同一次执行。
- GIVEN 真实 Codex 任务使用已确认的模型和档位，在独立测试目录内有一项会发起审批的工具操作
- WHEN 用户在运行中查看任务详情，并同意执行该工具操作
- THEN 回合结束前可看到多段正文逐步出现，Codex 公开的思考内容与正文分开展示。能按同一次工具调用查到操作名称、状态、可查看的输入输出、审批原选项、决定者、决定时间及最终结果。未收到公开思考时显示未上报

场景2: 拒绝一次工具操作
必要性：沿用现有拒绝行为及本轮审计要求；缺少时可能把拒绝过的操作误记成已执行。
- GIVEN 该次运行有一项待审工具操作
- WHEN 用户选择执行者提供的拒绝选项
- THEN 该工具操作按拒绝结果收口，审计保留原请求、实际拒绝选项和后续工具状态。工具决定与任务最终结果分别显示

场景3: 重试后查看先前的工具与审批记录
必要性：本轮要求可审计，现有任务详情主要展示当前运行；缺少时会在重试后失去旧运行的核对入口。
- GIVEN 同一任务已经有先前运行及工具审批记录，随后又产生一次运行
- WHEN 用户重新打开详情并查看先前运行
- THEN 可以分别查看各次运行的工具、审批与结果。记录归属保持可辨认，输入输出摘要或被截断的内容有标记

## feat03: 查看并对账任务消耗与上下文

分别查看任务用量与当前上下文，能核对每个数值的来源。

场景1: 对账同一真实任务的消耗和上下文
必要性：用户要求真实任务对账，并查看上下文占用和窗口；缺少时无法判断两个指标是否各自对应同次运行。
- GIVEN 真实 Codex 任务报告该回合用量和上下文观测
- WHEN 用户在运行中查看上下文，并在任务结束后核对该次运行的用量
- THEN 可分别看到当前占用、会话有效窗口、对应模型的标称窗口及来源。可查看对应回合的输入、输出、缓存、思考用量和已回报的总量，逐项与 Codex 原始回报核对。各项注明计量范围，已经计入总量的分项不再重复累计

场景2: 上下文整理后占用发生变化
必要性：上下文占用可能下降，任务消耗代表实际执行产生的用量；缺少时会把占用变动误认为用量增加或退款。
- GIVEN 同一次运行已显示上下文占用和窗口
- WHEN Codex 在整理上下文后报告新的占用
- THEN 详情展示最新占用及对应窗口，并保留可核对的观测记录。任务用量仍以 Codex 回报的实际消耗为依据

场景3: 执行器只回报部分指标
必要性：Codex 回报可能缺少某些用量分项或窗口值；缺少时会把证据缺失误读为零消耗或无占用。
- GIVEN 一次运行只有部分用量或上下文指标得到确认
- WHEN 用户查看该次运行和任务的消耗与上下文
- THEN 已确认值按原口径展示，缺失项标明未上报或未知，部分总量标明覆盖范围。模型目录提供的窗口值有单独来源标记

场景4: 重试后按运行查看和汇总消耗
必要性：明庭允许同一任务重试，且重复回报或重新打开详情可能再次出现旧记录；缺少时可能漏计前一次消耗或重复累计。
- GIVEN 同一个任务有多次运行，其中至少两次回报了可核对用量
- WHEN 用户重试完成后重新打开任务详情并查看各次运行和任务汇总
- THEN 每次执行的用量可独立核对，任务汇总按相同口径累计各次已确认用量。同一笔用量只计算一次，未上报的部分有缺项标记
