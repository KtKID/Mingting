# 同一任务的多轮沟通与通信计数

发布者可以在同一张任务单里分多轮委托执行、接收结果并继续沟通。明庭自动记录任务轮次（`taskTurn`）和逐条递增的通信序号（`seq`），每轮保留实际发单来源，便于查看任务的完整来回过程。

## 本次目标与完成条件

- 本次目标与范围　支持选择新建（`new`）或追加（`append`）。同一任务的后续内容追加到原单，任务轮次由明庭递增。发布者、明庭、执行者之间属于该任务的每条通信均计数，并能查看每轮来源。
- 验证证据　从孔明实际网页入口发起「杭州周末出行规划」，依次完成信息采集、行程方案生成、冲突核对与最终计划。逐轮核对同一张单、实际结果、来源会话和轮次、回执与唤醒，以及所有实际通信的顺序和总数。网页会话身份和唤醒关联由产品自动生成，测试者填写用户实际需要填写的内容。沿用[仓库验收约定](../../../AGENTS.md)。
- 完成条件　下列两个功能的六个场景符合预期。三轮执行在列表中对应一张单，详情可逐轮查看结果和来源，通信序号从首次发布连续累计，结果通知分别进入已登记会话，每条结果通知只开启一次对应续轮，其他会话收到零次。
- 关联范围　承接[统一发布与结果订阅需求](../unified-task-publishing/spec.md)中的发单回执、实际来源与结果通知约定。本次对同单多轮的归属、计数和后续决定权以下列约束为准。
- 确认依据　2026-11-07 本聊天中，用户明确要求同一任务包含多轮沟通，步骤改称轮次，每条通信递增计数，并确认需求已对齐、按剃刀法则整理。随后补充要求发单工具说明提醒同一任务使用追加。

## feat01 同一任务中分轮追加内容并接收结果

发布者通过新建开始一张单，通过追加继续同一任务。明庭自动分配任务轮次，每轮完成后按已登记的目标回传结果，后续由发布者决定。

任务清单分别显示「状态」和「轮次」。进行中的任务及已取消的任务显示「第 N 轮」，已完成或失败的任务显示「共 N 轮」。

**场景1　新建任务自动开始第 1 轮**

必要性　用户要求首次发布的任务轮次为 1。需要核对首次发单形成任务与首轮的对应关系。

- GIVEN 发布者准备开始「杭州周末出行规划」，第一轮内容为「信息采集」
- WHEN 发布者选择新建并提交任务内容
- THEN 明庭创建一张任务单，任务轮次自动为 1，回执包含该任务编号和任务轮次，执行者收到本轮内容

**场景2　追加两轮仍属于原任务**

必要性　用户提供的杭州规划由三轮组成，需要逐轮确认原单归属、结果交付与唤醒。

- GIVEN 第一轮「信息采集」已完成，发布者在已登记会话收到结果并继续处理
- WHEN 发布者向原任务追加「行程方案生成」，收到该轮结果后再向原任务追加「冲突核对与最终计划」
- THEN 两次追加分别自动成为任务第 2、3 轮，回执沿用原任务编号，列表中「杭州周末出行规划」始终只有一张单。每轮内容和实际结果可分别查看，每轮结果通知各在已登记会话开启一次对应续轮，其他会话收到零次

**场景3　发布者收到最终计划后仍可决定继续追加**

必要性　用户明确最终完成由发布者决定，前述真实任务的第三轮标题包含「最终计划」，需要覆盖这个具体触发条件。

- GIVEN 第 3 轮「冲突核对与最终计划」已执行结束，发布者已收到该轮结果
- WHEN 发布者决定继续处理并向原任务追加新的要求
- THEN 明庭将其记为原任务第 4 轮并交给执行者，任务编号沿用原值

**场景4　发单说明提醒同一任务使用追加**

必要性　用户明确要求在 MCP 描述中提醒发布者，选择追加是本次避免同一任务拆成多张单的发单指引。

- GIVEN 发布者准备通过 MCP 发单
- WHEN 发布者阅读发单工具说明
- THEN 说明明确提醒「同一任务的后续沟通使用 append，独立的新任务使用 new」，并说明追加时需选择已有任务

## feat02 查看逐条通信计数与每轮来源

用户可以沿着同一张单查看发布者、明庭与执行者之间的通信顺序和累计条数，并追溯每轮来自哪个会话及其发起轮次。

**场景1　通信序号跨轮连续累计**

必要性　用户要求每条实际通信递增，用于统计任务总共来回通信的次数，需要核对逐条记录及跨轮延续。

- GIVEN 「杭州周末出行规划」经历首次发布、三轮执行以及相应的回执和唤醒，过程中已记录全部实际任务通信
- WHEN 用户按顺序查看这张单的通信记录
- THEN 首次发布的通信序号为 1，之后每条实际通信的序号依次增加 1。进入任务第 2、3 轮时通信序号接着前一条累计，每条记录可查发送方、接收方、内容和时间，最后一个序号等于实际记录总条数

**场景2　每轮可追溯到实际发布会话**

必要性　用户要求保留发布者会话，并确认每轮保存完整来源。原杭州任务的发起会话轮次为 4、5、6，可用来区分两种轮次。

- GIVEN 发布者在同一个孔明会话的第 4、5、6 轮，分别新建任务和追加两轮内容，发单来源由宿主自动填写
- WHEN 用户查看明庭任务中三轮的来源记录
- THEN 任务轮次依次为 1、2、3，每轮均保存实际来源宿主和同一个发布者会话，发起会话轮次分别为 4、5、6，用户可据此追溯每次发单。任务通信序号按实际通信继续累计
