# 通用宿主完成唤醒

## ① 需求与变更

2026-11-08 用户确认明庭通用化 `events` 和 `ack`，删除 DSH 专用实现。范围为 [feat01](../spec.md#feat01-用统一规则发布任务并取得回执) 的会话绑定与 [feat02](../spec.md#feat02-订阅任务结果) 的完成唤醒。KMH 客户端由用户独立切换。起始工作区及并行变更见[基线](../../../../reports/host-wakeup/20261108-01/evidence/baseline.txt)。

## ② 精简技术设计

- D1 · 本机宿主使用各自的令牌和稳定 UUID。现有 `/wakeup-host/events` 与 `/wakeup-host/ack` 共用认证，每宿主一条连接。按宿主和会话归属投递、去重和确认。
- D2 · MCP 保留可信发布者元数据键，轮次接受数字或宿主原生字符串。持久投递目标只保存宿主与会话，来源继续保存在任务轮次。完成帧统一携带结果预览，移除版本头与发单轮次字段。
- D3 · 历史绑定读入时映射到新目标，保留原事件 ID、状态、发布去重指纹和已发凭据。已有 Codex ACP 投递沿用原契约。部署由本机宿主清单配置，无数据库重写。
- R1–R7 · 路由负责鉴权和流，发布服务保存来源，存储持久化事件，宿主开启会话。Zod 契约作为运行校验与客户端同步的唯一来源。结果长度沿用任务配置，确认采用现有事务和事件 ID。

## ③ 测试用例与变化

- T1 · 两个不同宿主使用相同会话 ID，分别发布、连接、收件；跨宿主确认拒绝，正确宿主可确认。
- T2 · 旧记录读取、补投、结果摘要和重复确认，原会话绑定与四轮追加回归。
- T3 · 配置文件、重复身份或令牌、原生轮次字符串、精简回执契约及构建检查。

## ④ 技术实现

- [通用宿主路由](../../../../src/server/transport/host-wakeup.ts)从宿主清单校验令牌，按宿主独立管理连接，统一发送完成预览并接收确认。保留并行改动中的长连接名额释放。
- [共享宿主契约](../../../../src/shared/host-wakeup.ts)定义发单来源、投递目标、完成事件及确认。[任务发布](../../../../src/server/tasks/publication.ts)分别持久化来源和目标，沿用去重指纹。[存储](../../../../src/server/storage/store.ts)读取既有绑定和事件。
- [接入与切换文档](../../../CHAT-WAKEUPS.md#通用宿主唤醒)说明宿主清单、MCP 元数据和事件字段。Codex ACP 的现有入口继续有回归覆盖。
