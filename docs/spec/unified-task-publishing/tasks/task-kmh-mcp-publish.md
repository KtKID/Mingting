# KMH 统一发单、结果订阅和原会话唤醒

> 功能依据 [统一发布明庭任务和订阅结果](../spec.md)
> 技术依据 [现有设计 D01–D04](../tech-design.md)
> 状态 已实现。四笔网页唤醒通过，交付对账保留模型行为缺口 · 2026-11-06

## ① 需求与变更

本轮用户要求走 x-qdev，孔明和普通会话共用 MCP 发单。60000 网页各发两笔，使用 zai-coding-cn 的 GLM-5.3。任务限于写入一个新的文本文件，完成后目标聊天各续一轮。范围为 feat01 场景 1、2、4、5 和 feat02。旧入口退役单独交付。基线为明庭 805d345 及已有工作区差异，KMH 5c97375。原定义与差异保存在本批报告附件。

## ② 精简技术设计

KMH 插件复用真实工具上下文和原有宿主 SSE。MCP 以认证后的元数据传送会话、轮次、可选目标和发布请求号。执行选用既有在线 Codex，网页发单与续轮使用用户指定的 GLM-5.3。明庭共用 TaskService.publish，在事务中保存任务、结果凭据哈希、发布指纹、绑定及领取记录。本次由明庭使用宿主凭据和稳定请求号派生同一重试凭据。回执由 KMH 原子写入私有目录。宿主在同一工具调用中重试一次传输，持久化发单绑定使明庭可在重启后按原请求补回执。宿主跨进程自动恢复未确认请求待验证。结果从 runs 读取，通过既有订阅端点的结果视图补收。协议由明庭 Zod 定义，沿用宿主生成契约。事件 ID 复用为会话队列请求号，输入落盘后确认。宿主通过请求头在同一条流中取得有界结果摘要，兼容原宿主事件字段。完整结果由订阅端点提供。

## ③ 测试用例与变化

- 新增明庭集成用例，覆盖设计 T1、T2、T3、T5、T7、T9 的服务端边界及结果回放。
- 修改 KMH 宿主集成用例并新增指定 B 的变体，核对默认会话 ID、MCP 元数据、回执响应丢失和重复事件入队。
- 沿用旧发布、旧审批及宿主投递用例。
- 新增 60000 浏览器验收，已有孔明和普通会话各两笔，逐笔比对文件、实际输出、原会话一轮和串投零次。

## ④ 技术实现

- 明庭 `src/server/http.ts` 挂接标准发布与订阅视图，`dsh-wakeup.ts` 复用认证及宿主流并提供结果摘要。
- 明庭 `TaskService.publish` 和 `Store` 在同一事务保存发布与回执。 `resultStatus` 校验凭据，`resultEvents` 从原运行读实际结果。
- `src/shared/{dsh-wakeup,protocol,task-wakeup}.ts` 提供权威契约。 `tests/dsh-wakeup.test.ts` 验证旧宿主与 MCP 新路径。
- KMH `packages/kmh-kongming/src/mingting.ts` 的 `publish` 发送标准 MCP，`saveReceipt` 保存私有回执，`deliver` 复用会话入队。同步生成契约、维护插件 README 和宿主回归。

## ⑤ 验证结果

明庭相关回归 70 项、KMH 宿主回归 2 项通过。60000 从两条已有聊天实际发四单，四个文件与订阅结果相符，各自一条完成事件、一次新轮次，84 份会话记录中其他聊天零次。K1 的原发单轮发生额外历史记忆操作，拦截后续轮正常启动。K1、K2 的续轮结果已出，额外记忆写入被拒绝或停止。功能正文与变更索引已同步。
