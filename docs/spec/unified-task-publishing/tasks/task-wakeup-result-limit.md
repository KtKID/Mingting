# 配置任务唤醒结果长度

## ① 需求与变更

用户要求将发送给唤醒者的结果上限从 1000 改为 5000，把数值放入按模块组织的 YAML 任务配置，并提交。承接 feat02 新增场景5。已有的结果订阅仍可读取保存的完整结果。[变更记录](../spec.md#变更记录)

## ② 精简技术设计

D01 沿用[宿主投递](../tech-design.md#host)与[结果订阅](../tech-design.md#results)。明庭在启动平台时读取根目录 `config.yaml`，用 Zod 检查 `tasks.wakeupResultTextLimit` 是正整数。宿主路由使用这一个值裁剪输出和错误，单位沿用 JavaScript 字符串长度（UTF-16 代码单元）。配置缺失或有误时在初始化数据库前报错，修改需重启明庭。宿主完成事件字段与任务结果的存储和订阅沿用既有协议。若 JSON 转义使消息超过 KMH 接收端的 16,384 上限，发送端进一步缩短预览并保留截断标记。

R1–R2、R4–R7 通过配置加载与传输分离、运行时校验、单一数值来源和真实事件流用例核对。R3 的跨语言同步不适用，宿主与明庭同用 TypeScript。

## ③ 测试用例与变化

- T01 修改标准 MCP 结果回归。默认配置下超过 5000 的输出在唤醒事件保留前 5000，截断标记为真。明庭详情和晚订阅读到完整输出。
- T02 修改宿主回归。隔离 YAML 使用另一个长度，确认事件按该长度回传，保留原宿主身份核验、审批和重连确认用例。
- T03 新增配置边界检查。错误类型和非法长度在启动配置阶段拒绝。
- T04 扩充标准 MCP 结果回归。包含大量转义字符的输出和错误在宿主消息上限内可解析，任务保留原文。

## ④ 技术实现

- `config.yaml` 保存按模块组织的配置。`package.json` 和锁文件增加 YAML 解析依赖。
- `src/server/config.ts` 的 `loadConfig` 读取并验证配置。`src/server/transport/http.ts` 的 `createPlatform` 把上限传给宿主路由。
- `src/server/transport/dsh-wakeup.ts` 的 `completionFrame` 从完整运行结果生成有界的唤醒事件。`src/shared/dsh-wakeup.ts` 移除原固定值。
- `tests/dsh-wakeup.test.ts` 覆盖 T01–T04，沿用裸 UUID 兼容回归。
