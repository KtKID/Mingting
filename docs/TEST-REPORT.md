# Task Platform MVP 0.2 验证报告

日期：2026-10-31。范围：在 `/workspace/task-platform-mvp` 补齐独立任务订阅、事件接收、领取所有权和执行回传。没有改动 MadeMe、Mac 或既有 Sites 演示，没有真实登录、读取现存凭据或调用模型。此前交付的 0.1 只有内部直接执行队列；0.2 已移除那条路径，改为订阅连接器领取后执行。

## 最终服务端结果

`npm run check`：**21 / 21 测试通过**，约 25.7 秒；随后 TypeScript 检查和 Vite 构建通过。使用 Node v24.19.0、官方 ACP SDK 2.2.0、MCP SDK 1.32.2、Codex ACP 2.5.0。转交的 ACP 负载通过 SDK 随附 JSON Schema 和 Ajv 8.20.0 校验。依赖安装禁用生命周期脚本，保留锁文件。

实际闭环为：

```text
官方 MCP HTTP 客户端 publish_task
→ SQLite 事务保存任务 + 持久通知事件
→ HTTP SSE 任务订阅客户端收到 task.available
→ HTTP 原子领取，得到 runId/ownerId/claimId
→ 现有 CodexAdapter 启动假 ACP 子进程
→ HTTP 转交原始 ACP 权限请求
→ 网页审批 API 处理
→ HTTP 查询决策后返回原 ACP callback
→ ACP session/update 和最终结果经 HTTP 顺序回传
→ SQLite 状态与网页列表更新
```

HTTP/SSE/数据库/领取/状态回传均为实物代码，不是 stub 函数。测试覆盖一个真正单独启动的连接器进程及真正独立的 ACP 测试进程。假 ACP 不调用模型或执行示例命令，因此这些结果**不等于真实 Codex 工具审批已联调成功**。

21 项覆盖：

1. 真实 HTTP MCP 列出唯一 publish_task；不存在的审批工具失败；发布→订阅接收→领取所有者→假 ACP 审批→结果回传；后续任务保持串行排队。
2. 原始拒绝选项回传；伪造选项、错误 run/session 被拒绝。
3. 取消后旧审批失效，重试创建不同 run 和新审批。
4. 停止、重启后任务保留，旧运行中断、旧审批过期，无回调复活。
5. 恶意 Host/Origin、缺失会话/CSRF、非法字段和客户端传 cwd 被拒绝。
6. ACP 子进程异常退出使当前任务失败，后续任务仍能执行。
7. 非当前 ACP session 的权限请求直接取消，不登记或批准。
8. 重构崩溃持久记录后重启：旧运行恢复为 interrupted，旧审批 expired，排队任务经恢复等待期后继续；旧任务不自动重跑。
9. 推进服务端截止检查：审批超时取消任务，迟到决策返回 409。
10. 显式认证方法经 ACP 协商，使用假方法、不使用真实密钥；默认不会自动 authenticate。
11. 取消后立即关停并重启，保留 cancelled 状态。
12. 先建立 SSE，再通过真实 HTTP MCP 发布：客户端收到持久事件；仅接收事件时任务仍 queued、没有 run。
13. 无连接器时发布，平台重启后晚到的订阅者补收事件，再经领取/ACP/人工决策/状态回传完成。
14. Last-Event-ID 重连按顺序补收断线期间的任务；从 0 重新订阅会有意重发已有事件。
15. 并发领取仅一方成功，同 owner/claimId 重试返回相同 run；错误所有者被拒；重复报告幂等、序号缺口被拒；领取并不自动标记成功。
16. 两个真实 HTTP 订阅客户端收到同一事件，只有一个运行实际进入 ACP 执行，结果中没有重复 run。
17. 等待审批时心跳续约，后续任务保留 queued；断开并重连订阅流后取消，旧运行终止并释放后续任务。
18. 启动独立连接器 Node 进程，收到任务并进入审批后 SIGKILL；截止检查使租约失效、审批过期；新订阅者可执行后续任务，原任务不自动重跑。
19. SSE 拒绝浏览器 Origin 和未来游标；HTTP 转交的非法 ACP 通知被官方 schema 拒绝，未推进报告序号。
20. 连接器的工作区与平台配置不一致时，在启动 ACP 前报告失败，没有 session/discovery。
21. 故意使假 ACP 忽略 EOF 和 SIGTERM 并挂起；取消后强制进程清理完成，后续任务进入审批。该用例约 5.3 秒，证明此故障不会永久占用串行槽位。

测试 9、18 使用服务端截止检查入口推进时间，不需要真实等待 10 分钟/租约完整时长；正常心跳续约与取消释放使用真实 HTTP 时间流程。它们验证状态转移和恢复逻辑，不是时钟精度或负载压测。

## 故障和等待的区别

- 待订阅/排队：没有连接器也可以发布，任务和事件保留。
- 人工审批：明确 awaiting_approval 并持续心跳；单并发下后续任务等待是设计行为，可决策/取消/超时结束。
- 连接器故障：心跳租约 8 秒失效后中断，审批失效、槽位释放；需重启连接器继续领取，原任务只允许显式重试。
- 取消清理：保留运行所有权到终止回传或租约过期；网页先显示停止中，防止原进程还没停就重试。
- 重启恢复：若有旧执行，最多 8 秒恢复等待期让旧连接器停止，再接受新领取。领取能力和报告序号防止旧进程改写新运行。

以上是可信本机、单服务实例、单 Codex 类型连接器的 MVP 保证。至少一次通知和领取互斥不是业务文件修改的 exactly-once 或事务回滚保证。持久事件日志暂不清理；未做大规模压力、多实例数据库、远程鉴权或全部故障的形式化证明。
