# Agent 任务城市：最终效果与落地路线

> 适用于 Agent 任务城市（three.js 参数化古建）。
> - **第一部分（第 1–5 章）**：最终效果，城市如何随任务量、人数增长，府邸如何越来越豪华。
> - **第二部分（第 6–11 章）**：怎么落地，先用白模验证“数据到视觉”，风格作为渲染层后加；但有 6 样东西必须在白模阶段预留。

# 第一部分：最终效果（城市如何越来越繁荣）

## 1. 核心原则：成长只增不减，状态可升可降

把“繁荣”拆成两个互相独立的信号，否则城市要么只会膨胀、失真，要么忽大忽小、没有成就感。

| 信号 | 特点 | 画面表现 |
|---|---|---|
| **累计成熟度**（质量加权的合并 PR、完成任务等） | 只增不减 | 府邸等级、院落进数、斗拱、石狮、园林、城市规模 |
| **当前健康度**（近期流转、积压、周期时间） | 可升可降 | 窗灯、炊烟、杂草、门口排队、河道淤塞 |

所以：**府邸一旦升级就不会降级**；项目停摆只会灯灭、长草，不会塌。这样“越来越繁荣”是真实可累积的，同时不丢失“现在哪里出问题”的观测价值。

## 2. 三个尺度的成长

### 2.1 城市：村 → 镇 → 县城 → 府城 → 都城

由全城累计成熟度驱动，靠里程碑解锁，城墙逐级外扩。

| 阶段 | 画面 | 解锁内容（示例） |
|---|---|---|
| 村 | 几间茅舍、土路、一口井，军机阁只是一座小亭 | 榜亭（任务发布与认领） |
| 镇 | 有了河埠头、集市、石板路 | 工部（CI）、码头 |
| 县城 | 有城墙与城门、坊墙成形 | 御史台（定时 review）、观星台 |
| 府城 | 城墙外扩，出现钟鼓楼、书院 | 粮仓扩建、藏书楼（归档项目） |
| 都城 | 宫城式的军机阁，中轴线与朱雀大街 | 邸报馆、回放与天灾演练等高阶功能 |

> 以上阈值是起点值，要按你 30 个项目的真实产出速度来调。建议相邻阶段的门槛按 2–3 倍递增：早期升级快，让成就感来得早；后期慢，保持长线目标。

### 2.2 人口：越来越多的人

人口分两类，必须区分开：

| 类别 | 对应 | 说明 |
|---|---|---|
| **常驻居民（有数据的）** | 每个 agent 一个有名字的人物 | 官阶由合并率、返工率、review 通过率决定：白丁 → 吏 → 主簿 → 县令 → 太守。官阶越高，服饰、仪仗越讲究（轿子、随从） |
| **市井路人（装饰）** | 无对应数据 | 数量随城市阶段和吞吐增长，营造“热闹”，但要明确标注为装饰，不参与判断 |

“人越来越多”真正的信息来源是：**agent 数量增加、官阶分布变高、同时在途的任务变多**。

### 2.3 府邸：越来越豪华

每个项目一座院落，由该项目累计成熟度决定等级。**数值是示例，可调。**

| 等级 | 累计成熟度（示例） | 建筑与装饰 | 对应 `buildHall` 参数（示意） |
|---|---|---|---|
| L0 茅庐 | 0 | 单间茅草顶、土墙，无围墙 | bays 3, depth 1, 硬山, tiers 0 |
| L1 瓦房 | 10 | 三开间灰瓦、木门，门前一条小路 | bays 3, depth 1, 硬山, tiers 0 |
| L2 一进院 | 40 | 围墙加门楼，院中一棵树 | bays 3–5, depth 2, 悬山, tiers 0 |
| L3 二进院 | 120 | 垂花门、石狮一对、红灯笼、斗拱 | bays 5, depth 2–3, 悬山或歇山, tiers 1 |
| L4 三进加楼阁 | 300 | 跨院、阁楼、影壁、彩画、牌坊匾额 | bays 7, depth 3–4, 歇山, tiers 2, 局部重檐 |
| L5 府邸 | 700 | 园林（假山、池塘、亭）、旗杆、私家码头、重檐 | bays 7–9, depth 4, 歇山或庑殿, tiers 3, 重檐 |

**与之前参数绑定的小调整**：

- `bays`（开间）仍绑定项目规模，`roof`（屋顶）仍绑定项目重要度，两者独立于等级。
- `depth`（进深/进数）和 `tiers`（斗拱）改为随累计成熟度升级。原先 `tiers` 绑活跃度，但活跃度会波动，斗拱会时有时无；绑累计值更稳。
- 黄琉璃等“皇家等级色”慎用：只留给军机阁等核心建筑，避免 30 座院落都金光闪闪，失去等级对比。

## 3. 防刷与防失真

- **按质量加权，而不是按数量。** 只算合并且未被 revert 的 PR，一次通过 review 的加权更高，周期时间长的打折。
- **边际递减加日封顶。** 用对数或分段，避免靠堆小 PR 刷等级。
- **等级不降，状态会变。** 荒废只表现为灯灭、长草，主动归档的项目入藏书楼，体面退场。
- **永久地标记录里程碑。** 比如第 100 个、第 1000 个合并 PR 立碑，作为只增不减的荣誉。
- **城市升级由全城累计驱动，但同时要求有一定比例的健康项目**，避免靠一两个高产项目撑起整座城。

## 4. 成长的“仪式感”

繁荣不只是数值变化，要让用户感受到“长大”：

1. **施工过程可见**：升级时先搭脚手架、工匠施工，竣工后再亮灯。
2. **竣工与解锁播报**：用古风《邸报》发布，例如“某某项目建成二进院”“城邑升为县城，增设御史台”。
3. **里程碑动效**：升级瞬间放一次鞭炮、点亮灯笼，节奏要克制，只在重要节点出现。
4. **回放**：事件流支持时间回放，可以看着一座村怎样长成都城，这是最适合截图和传播的画面。

## 5. 最终画面：一开始与成熟之后

| | 一开始 | 成熟之后 |
|---|---|---|
| 城市 | 小村，只有榜亭，周围大片留白 | 都城，城墙外扩，河上船只往来，中轴线清晰 |
| 府邸 | 30 个项目大多是茅庐、瓦房，零星几处灯亮 | 活跃项目是灯火通明的多进院和府邸，沉寂项目灯灭长草但仍在 |
| 人 | 少数几位小吏 | 各官阶 agent 分布各坊，路上有仪仗与市井人群 |
| 信号 | 极少，几乎没有堵点 | 堵点一眼可见：某处河道淤塞、某坊门口排队、某府邸炊烟断绝 |

**一句话概括**：*累计决定“长得多大、多华丽”，状态决定“现在亮不亮、堵不堵”；前者给成就感，后者给观测价值。*

# 第二部分：落地路线

> 以下章节为此前整理的“白模优先、风格后置”。

## 6. 可以后加的（渲染层）

这些只改渲染管线或材质，不动场景结构，可以整体替换：

- bloom、雾、色调映射、调色
- 描边（深度/法线边缘检测，或反壳法）
- 卡通着色、平涂
- 光照方案、昼夜循环、阴影风格
- 远景云雾

## 7. 必须现在预留的

后处理救不了结构问题，这些如果白模阶段没留好，后面会返工。

| 要预留的 | 原因 |
|---|---|
| 剪影和比例 | 屋顶轮廓、台基比例决定辨识度，渲染再好也改不了形体 |
| 部件拆分 | 台基、柱、墙、斗拱、屋顶各自独立，才能分别上材质、做分层动画 |
| 材质语义化 | 用 `M.wall`、`M.roofImperial` 这类语义材质，不直接写颜色，换风格只改一张表 |
| 信号通道与风格通道分开 | 窗灯、炊烟、排队等数据信号走自发光、实例颜色或 uniform，不依赖材质外观 |
| 布局、间距、模数 | 用户一旦记住位置就不能再动 |
| LOD 层级 | 远景聚合、中景院落、近景细节，决定几何怎么组织 |

最关键的是第 3、4 条：如果“状态”靠“楼被染成黄色”表达，换风格时信号就丢了；信号独立成层，风格怎么变信号都成立。

## 8. 白模阶段怎么做

- **不要完全无信号。** 保留灰阶加 2–3 个信号通道：窗亮灭、炊烟、门口排队、一种告警色，否则无法验证“能不能看出堵点”。
- **灰阶可读性本身就是测试。** 白模下状态仍读得出来，说明信号设计稳，风格只是加分。
- **形体别过度打磨。** 屋顶曲线、斗拱细节、匾额等风格确定后再精修。
- **匾额先占位。** 留好写项目名的面片位置，之后再换书体。

## 9. 一个提醒：别把风格推到最后才碰

在白模阶段中间留半天做**渲染技术验证**：在目标设备上跑一次描边加 bloom，确认帧率和兼容性。重点关注：

- 透明物体与 bloom 的配合
- 后处理在移动端的开销
- 描边依赖的法线或 ID 缓冲

这些会反向约束场景组织方式，早知道才不会走错路。

## 10. 建议顺序

| 阶段 | 内容 | 产出 |
|---|---|---|
| 1. 白模加信号 | 数据到几何，数据到光和烟 | 验证可读性 |
| 2. 渲染验证（约半天） | 描边加 bloom 跑一遍 | 确认技术可行，不求好看 |
| 3. 风格迭代 | 色板、描边、光照、雾 | 反复试，选定风格 |
| 4. 美术精修 | 屋顶细节、匾额、小道具、装饰 | 最终视觉 |

## 11. 快速自检

把之前的 `buildHall` demo 里所有材质换成同一个灰色，看开间、进深、屋顶等级的差别是否仍然分得出来。分得出，说明形体语言过关。
