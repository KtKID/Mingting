## ① 需求与变更

本轮用户授权完善 Web：新 tab、新页面、按项目区分，重点是任务状态正确，后续 3D 小镇复用数据。采用项目切换、Spec 分行、Task 按状态分列，并保留原任务台。来源为项目内 x-dev-pipeline 文档。用户明确确认 C 布局及左侧竖直导航。每个项目可同时显示多个 Spec，各自拥有独立任务；Spec 同行卡片共用前缘颜色条，阻塞使用单独文字提示。

基线为任务开始时 Git HEAD 和工作区状态；已有 `.DS_Store`、`.video_agent/` 保留。本轮新增独立记录模块，通过现有 HTTP/MCP 组合入口和 SQLite 持久层接入。

## ② 精简技术设计

| ID  | 方案与数据流                                                                                                                                                                                                                                        | 依据               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| D1  | `shared/project-records.ts` 定义 Zod 项目/Spec/Task/步骤/来源/同步契约，前后端推导类型。阶段与阻塞分别保存，统计由 Task 派生                                                                                                                        | C2/C3/C4，R2/R4/R5 |
| D2  | 本机导入器读取 `docs/spec/*/spec.md`、`tasks/task-*.md` 和 `tasks/*/dev-checklist.md` / `dev-report.md`，显式状态优先并提示清单失败冲突，历史报告的通过数和总数须与当前清单匹配，技术设计保持文档引用。限定来源路径和文件大小，原子写入一份项目快照 | C2/C3，R1/R4/R7    |
| D3  | 记录采用独立 SQLite 表，经 Store 公共方法读写。项目根的规范路径与 Spec/Task 相对路径形成稳定来源 ID；重复同步按内容指纹更新，失败保留旧快照并记录错误。已接入项目由可关闭的周期核对器刷新                                                           | C1/C4，R1/R4/R6/R7 |
| D4  | `/mcp` 新增 `sync_project_records` 接入/刷新项目，GET `/api/project-records` 提供同一份记录；文档读取以项目 ID 和已登记来源路径校验。全部记录路径保持独立于执行任务的发布、领取与唤醒                                                               | C1/C4，R2/R7       |
| D5  | `/records` 新页面，任务台和项目记录共享左侧竖直导航；项目切换下以 Spec 聚合 Task、按状态列显示。颜色从未筛选的 Spec 列表分配，同一 Spec 的颜色应用到该行所有卡片。窄屏可横向滚动看板，详情支持键盘关闭                                              | feat02，C2/C4      |

同步周期与输入容量使用具名常量。项目资料保留原地，明庭保存供统一查询的观察快照。源版本是内容哈希；观察时间和文档声明的时间分别呈现。当前 source ID 对项目根路径和文档路径稳定，移动/改名视为新来源，后续迁移按实际需要处理。

## ④ 技术实现

- `readProjectRecord` 从项目文档提取 Spec、Task、步骤和完成依据，使用项目根路径与来源路径生成身份。
- `ProjectRecords.sync`、`ProjectRecords.refresh` 和 Store 的项目记录方法接入、更新和保存快照；失败保留上次成功记录。普通 MCP `sync_project_records` 与网页共享 Zod 回执。
- `PageNav` 与 `ProjectRecordsPage` 提供左栏和 C 看板，`TaskDetail` 同时呈现项目、Spec、Task 及来源。颜色从当前项目未筛选的 Spec 顺序确定。
- `tests/project-records.test.ts` 覆盖导入、状态、持久化和真实协议；`tests/project-records-ui.spec.ts` 覆盖桌面与窄屏；`tests/platform.test.ts` 的既有回归工具清单纳入新增项目记录工具。
