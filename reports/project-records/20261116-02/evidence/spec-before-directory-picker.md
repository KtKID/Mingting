# 项目记录：集中查看各项目的开发进度

> 模块：project-records
> 管哪些代码：src/shared/project-records.ts、src/server/records/、src/web/project-records.tsx
> 状态：已完成
> 最近更新：2026-11-16

项目记录从已接入项目的 x-dev-pipeline 文档读取 Spec、Task、内部步骤和交付依据，供 Web 与后续其他展示客户端共用。

## 本次目标与完成条件

- 在新页面 `/records` 按项目查看 Spec 分行、Task 按阶段分列的看板，左侧竖直导航在任务台和项目记录之间切换，保留任务台原有功能。
- 使用项目内真实文档生成记录；支持目录形式 checklist/report 与单文件 qdev；同步保留来源、内容版本和观察时间。
- 使用明庭 Codex 设置与审计 Spec 验证 5 个 Task、19 个内部执行项的真实映射；用隔离项目验证状态变化、跨项目隔离、持久化和零执行副作用。

## feat01: 按项目同步开发记录

场景1：用户通过普通 MCP 或网页接入本机项目后，明庭显示其 docs/spec 下的 Spec 和 Task；重复同步保留同一来源的身份。

场景2：已接入项目文档发生变化后，后续刷新同步显示新状态；后台周期核对提供持续更新。读取失败时保留上次记录并显示同步错误和最后成功时间。

场景3：同步第二个项目、重启服务或重复同步后，各项目记录保持独立，既有执行任务和运行数量保持原值。

## feat02: 通过新页面掌握进度

场景1：用户通过左侧竖直导航进入“项目记录”。切换项目后，该项目的多个 Spec 同时分行呈现，各自的多个 Task 归入该行的待开始、进行中、待验收、已完成、待核对列。同名 Task 保留各自的项目、Spec、阶段和来源。

场景2：用户搜索、切换关注筛选、打开 Task 后，能查看该任务的状态依据、内部步骤及文档；窄屏可浏览所有状态并操作详情。

场景3：空项目、首次加载、同步失败、来源缺失分别有可读反馈；阶段由列标题和状态标签表达。同一 Spec 的卡片共用一种位于前缘的颜色条，颜色对应 Spec 身份。阻塞在卡片内单独标记，颜色条继续标识 Spec。

## feat03: 保持状态可追溯

场景1：Task 显式状态优先；当任务标为已完成但清单存在失败项时，显示待核对和冲突原因。基于清单推断完成须同时满足全部步骤通过和报告的通过数、总数与清单当前步骤数一致；仅步骤全绿的任务进入待验收；资料不足时显示待核对。

场景2：每条记录带稳定来源身份、来源文档与内容指纹；同步时间表示观察时间。文档访问限定于已登记项目下记录引用的 docs/reports 文本文件。
